### Summary

collection 的两条发布轨（GitHub→Galaxy 与 Forgejo）改为「先准备、后打 tag」的不可变发布模型，release tag 改用**裸 SemVer**（例如 `0.3.0`，不带 `v`）：

- 发布前本地完成 bump `galaxy.yml` + `make changelog` + commit，然后在该提交上打裸 tag；
- workflow（触发条件 `[0-9]*`）检出 tag 本身并校验（纯 SemVer、与 `galaxy.yml` 版本一致、HEAD 恰为该 tag），构建后发布——不再在 CI 里 bump 版本、不回写分支、不移动 tag；
- Forgejo release body 改取该版本 changelog 的 `release_summary`。

裸 tag 是 collection 生态的主流惯例；且 `ansible-galaxy` 安装 `type: git` 源时把 `version:` 当 git ref 解析，tag 与版本号同名后，消费端才能直接写 `version: "X.Y.Z"` 安装。此前旧模型还有一个隐蔽缺陷：tag 打在 bump 之前的提交上，按 tag 安装得到的 `galaxy.yml` 版本是上一版的——新模型一并修复。

role 的两条发布轨（git-cliff / release-please）与脚手架自身的 `v*` tag 不变。

### Upgrade Notes

仅影响 collection artifact（role 无变化）：

- `copier update --trust` 引入新 workflow 后，发布流程改为：bump `galaxy.yml` → `make changelog` → commit → `git tag X.Y.Z`（不带 `v`）→ push tag。
- 旧的 `v*` tag 保留即可：新触发条件（`[0-9]*`）不匹配它们，不会误触发。不要为旧版本补推裸名 tag（会重复触发发布）。
- 已手工切换到该模型的仓库（operations、restic）update 后这些文件零变更。
