### Summary

修复三个 CI 和 molecule 问题（#20、#21、#22），role 和 collection 都受影响，collection 的改动更多：

- **collection 的 molecule 直接从工作区解析 collection，不再往 `~/.ansible` 装副本**（#20）。molecule 每条命令前的 prerun 会把被测 collection 装进 `~/.ansible/collections`，工作区一改，这份副本就过时了；ansible-lint 会警告 "Another version ... was found"，并且按 FQCN 解析到旧代码。现在由新增的共享配置 `.config/molecule/config.yml` 处理：
  - 关掉 prerun；
  - 把 collection 所在的目录树放在 `ANSIBLE_COLLECTIONS_PATH` 的最前面，后面接 Ansible 的默认路径；
  - 原来每个场景里重复的 `ANSIBLE_ROLES_PATH` 也挪到这里。
  molecule 会把每个场景的 `molecule.yml` 合并到这份配置上，所以以后新加的场景也会自动生效。
- **molecule 实例不再因为同名而互相删除**（#22）。所有 job 共用宿主机的 Docker daemon（DooD），而实例名是固定的：
  - 生成的 Forgejo `molecule.yml` workflow 加了 `concurrency`，同一个仓库的运行排队执行，不会互相取消；
  - collection 示例场景的实例名带上了 collection 名（`<collection_name>-example-debian13`、`-example-vm`，名字里的 `_` 换成 `-`），不同 collection 之间也不再撞名。
- **删掉 Forgejo workflow 里的 `permissions`**（#21）。Forgejo Actions 会忽略这个字段，写了反而让人以为权限受到了限制。生成的 role 和 collection 的 Forgejo `release.yml` 都去掉了它，`.github/` 下的保持不变。

builder 镜像没有变化，继续使用 `builder/v1.3.0`。

### Upgrade Notes

已生成的 role 和 collection 执行 `uvx copier update --trust --defaults` 即可。

**collection：删一次旧副本。** 以前跑 molecule 留下的副本不会自动消失，ansible-lint 会继续用它：

```bash
rm -rf ~/.ansible/collections/ansible_collections/<namespace>/<name>
```

**collection：`galaxy.yml` 的依赖要写进场景的 `collections.yml`。** prerun 关掉之后，`galaxy.yml` 的 `dependencies` 不再被自动安装，只有各场景 `collections.yml` 里列出的会由 `dependency: galaxy` 安装。模板生成的本来就两边都写了；自己加的依赖，确认每个用到它的场景都列了。

**collection：场景里的 `env`。** update 会删掉各场景 `molecule.yml` 里的 `ANSIBLE_ROLES_PATH`。场景自己额外加的 `env`（比如 `ANSIBLE_PIPELINING`）保持不变，会和共享配置合并。自己设过 `ANSIBLE_COLLECTIONS_PATH` 或 `prerun` 的场景会覆盖共享配置，需要确认是否还需要。

**collection：实例改名。** 示例场景的实例名会变。update 之前创建、还没销毁的实例，先用旧名字销毁（在 update 之前跑 `make destroy`，或者直接 `docker rm -f example-debian13`）。

**Forgejo 的 `release.yml` 和 `molecule.yml`：** 删掉 `permissions`、加上 `concurrency` 这两处改动，在手工改过这两个文件的仓库里可能冲突，取模板一侧即可。
